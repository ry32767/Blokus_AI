# blokus-selfplay (native Rust core)

A native (Rust, edition 2021) port of the **Blokus Duo** deterministic game core and
state encoder, plus a self-play scaffold. The long-term goal is **fast local
self-play** to replace the slow Node + `onnxruntime-web` path in `training/`.

It now also provides **ONNX policy/value inference** (behind the `onnx` cargo
feature) and a **negamax PUCT MCTS self-play actor** (`src/mcts.rs`) ported
exactly from `apps/web/src/ai/policyValueMctsAi.js`, so native self-play can use
the neural net just like the JS engine.

> **Unverified — authored without a local Rust toolchain.** Nothing here has been
> compiled or run. **Run `cargo test` (no features) and `cargo build --features
> onnx` locally before relying on any of it.** The no-onnx `cargo test` covers the
> deterministic core (`tests/parity.rs`) plus the MCTS invariants in
> `src/mcts.rs` (`UniformPolicyValue`).

> Design rationale, the parity contract, and the staged roadmap live in
> [../../../docs/NATIVE_SELFPLAY.md](../../../docs/NATIVE_SELFPLAY.md). This README is the
> crate-local API/usage reference.

## What it is

- `src/lib.rs` — public API mirroring the JS core (`packages/core/src/*.js`):
  - `constants` — `BOARD_SIZE=14`, `EMPTY=-1`, start points `A=(4,4)`, `B=(9,9)`,
    orthogonal/diagonal direction tables, `STATE_PLANES=51`.
  - `orientation` — loads the **91 orientations** from
    `packages/core/src/orientations.json` (embedded via `include_str!`; **not**
    hardcoded). `PIECE_IDS` order matters and matches `pieceIds.js`.
  - `board`, `rules` — `create_initial_state`, `generate_legal_moves`,
    `generate_legal_placements_for_player`, `apply_move`, `is_terminal`. Move
    iteration order, first-move start coverage, edge-vs-corner contact, and
    chooseStart assignment all mirror `rules.js` exactly.
  - `scoring` — `score_player` / `score_state` (`-remaining + 15 if cleared + 5 if
    last placed `I1`).
  - `action` — `encode_action` / `decode_action`, `ACTION_SIZE=17837`,
    `PASS_ACTION=17836`.
  - `encoding` — `encode_state_tensor` → `Vec<f32>` of length `51*14*14 = 9996`,
    plane→y→x order, with the player-perspective 180° flip for player 1.
  - `inference` — `PolicyValue` trait (`infer` / `infer_batch`). `UniformPolicyValue`
    (zero logits + value 0, no native dep) is always available; `OnnxPolicyValue`
    (behind `--features onnx`) loads `blokus_policy_value.onnx` and runs
    `[N,51,14,14] → (policy_logits[N,17837], value[N])` via the `ort` crate.
  - `mcts` — negamax PUCT MCTS, a faithful port of
    `apps/web/src/ai/policyValueMctsAi.js`: node value in the to-move perspective,
    backup negates once per ply, lazy child states, softmax priors truncated to
    `candidate_limit`, an NN-output transposition cache (NOT a tree gate), seeded
    Dirichlet root noise, temperature move sampling, and a **visit-count
    distribution** policy target (NOT one-hot).
- `src/bin/selfplay.rs` — plays N games with either a deterministic random-legal
  policy (`--policy random`, default) or NN-guided MCTS (`--policy mcts`) and writes
  JSONL matching the Python trainer schema.
- `src/bin/parity_check.rs` — runnable parity checker (PASS/FAIL per check) that does
  not need the test harness.
- `tests/parity.rs` — the authoritative parity test against
  `../parity/golden.json`.

## Parity guarantee

Parity is the #1 requirement. The Rust core **must** reproduce the JS/Python rules and
encoders byte-for-byte; a trained model would otherwise be fed inconsistent inputs at
inference. The golden reference at `training/native/parity/golden.json` (generated by
`training/native/parity/gen_golden.mjs`) is the contract. `tests/parity.rs` asserts:

- `orientationCount==91`, `actionSize==17837`, `passAction==17836`, start points
  `A(4,4)/B(9,9)`.
- Initial legal-move counts: `chooseStart==828`, `fixedStart==414`.
- Action round-trips (`decode` then `encode` is the identity; decoded
  piece/orientation/x/y match).
- Scoring edge cases: `blankFinishedP0==-89`, `allPlacedLastI1==20`,
  `allPlacedLastI2==15`.
- Two fully replayed deterministic games (`fixedStart`, `chooseStart`): at each ply,
  `legalMoveCount`, `selectedAction`, `scoreA/scoreB`, and the canonical SHA-256 of the
  board and of the current-player state tensor all match.

Canonical serialisations (must match `gen_golden.mjs`):

- **board byte**: `cell == EMPTY(-1) ? 0 : (cell + 1)`, row-major (`index = y*14 + x`),
  then sha256-hex.
- **state bytes**: `f32` little-endian of the flattened tensor (plane→y→x), then
  sha256-hex.

## Build / test

This crate was **authored without a local Rust toolchain**, so it has not been compiled
or run here. **The first step is to validate parity** — from the repo root via the npm
wrappers, or with `cargo` directly inside this crate:

```bash
# from the repo root:
npm run native:test                         # = cargo test (tests/parity.rs against golden.json)
npm run native:selfplay -- --games 10 --out games.jsonl --seed 1

# or directly inside the crate:
cd training/native/blokus-selfplay
cargo test                                  # runs tests/parity.rs against golden.json
cargo run --bin parity_check                # same checks, prints PASS/FAIL per item
```

Once parity passes, generate self-play data with the random scaffold:

```bash
cargo run --release --bin selfplay -- --games 10 --out games.jsonl --seed 1 --start-policy fixedStart
```

Or run the **NN-guided MCTS** self-play (requires the `onnx` feature + onnxruntime):

```bash
cargo run --release --features onnx --bin selfplay -- \
    --policy mcts \
    --model ../../../apps/web/public/models/blokus_policy_value.onnx \
    --games 50 --sims 200
```

`--policy mcts` **without** `--features onnx` (or without `--model`) falls back to
`UniformPolicyValue`, so the binary still runs everywhere — useful for shaking out
the search wiring before linking onnxruntime.

### `selfplay` flags

General: `--games N`, `--out FILE`, `--seed S`, `--start-policy
chooseStart|fixedStart`, `--policy random|mcts` (default `random`).

MCTS (`--policy mcts`): `--model PATH`, `--sims N` (max simulations per move),
`--time-ms MS` (per-move budget; `0` = unbounded → relies on `--sims`),
`--candidate-limit N` (default 120), `--exploration-c F` (default 1.5),
`--root-dirichlet-weight F` (default 0.25), `--root-dirichlet-alpha F` (default 0.3),
`--mcts-sampling-temperature F` and `--mcts-sampling-plies N` (sample
`visits^(1/T)` while `turn < N`, else argmax). If neither `--sims` nor `--time-ms`
is given, `--sims` defaults to 200 so the run terminates. All randomness is seeded
(derived from `--seed`), so MCTS self-play is reproducible.

In `random` mode the `policy_target` is a one-hot on the played action. In `mcts`
mode it is the **MCTS visit-count distribution** (the AlphaZero policy target),
which is what makes self-play data valid for training.

### ONNX feature / onnxruntime

The `onnx` feature is **off by default** so the crate and `tests/parity.rs` build
without the onnxruntime native library. `cargo build --features onnx` pulls in the
[`ort`](https://crates.io/crates/ort) crate (v2 rc), which by default
auto-downloads a matching onnxruntime binary (`download-binaries`). If that native
lib is unavailable in your environment, a **pure-Rust fallback** is documented as an
alternative: swap the dependency to [`tract-onnx`](https://crates.io/crates/tract-onnx)
and reimplement `OnnxPolicyValue::load`/inference in `src/inference.rs` (same trait,
same `[N,51,14,14] → (logits[N,17837], value[N])` contract).

### JSONL output schema (per position)

Matches `training/generate_dataset.mjs` / `training/train_policy_value.py`:

```json
{"player":0,"encoded_state":[...51*196 floats...],"legal_actions":[...ints...],"selected_action":123,"final_score_diff":-6,"policy_target_actions":[123,456,...],"policy_target_probs":[0.62,0.21,...],"root_value":0.137}
```

`final_score_diff` is filled after the game from the position's player perspective
(black−white for P0, white−black for P1), as in `generate_dataset.mjs`.

`policy_target_actions` / `policy_target_probs` are a one-hot in `random` mode and
the MCTS visit distribution (actions sorted by visits desc, `probs = visits/total`)
in `mcts` mode. `root_value` is the root NN/terminal value in the position player's
perspective (`0.0` in random mode).
