# コードレビュー結果（2026-07）

リポジトリ全体（core / web AI エンジン / 学習パイプライン / Python / Web UI / native）を対象にしたバグ監査の結果。
**A 節は今回修正済み**、**B 節は未修正の修正案**（設計判断・再学習を要するもの）。

## A. 修正済み

### A-1. 【致命的】MCTS 終端ノードの negamax 符号反転
- `apps/web/src/ai/mctsAi.js` / `apps/web/src/ai/policyValueMctsAi.js` の `finalValueForToMove`、および Rust ミラー `training/native/blokus-selfplay/src/mcts.rs`。
- `advanceTurnOrFinish`（`packages/core/src/rules.js`）は終局時に `currentPlayer` を交代**しない**ため、終端状態の `currentPlayer` は「最後に打った側」= 親ノードの手番側。leaf 値を `currentPlayer` 視点で返すと、backup の 1 回反転で親に**逆符号**で伝わる。
- 影響: 両 MCTS エンジンが「勝ちの終局手を避け、負けの終局手を選ぶ」方向に探索。`ai_runtime.mjs` 経由の自己対戦の visit 分布ターゲット（終盤付近）も汚染されていた。**この修正以前の終盤付近の自己対戦データは信頼できない。**
- 修正: 終端 leaf 値を「打った側の相手」視点に反転。JS×2 / Rust を同時修正、`parity:golden` 再生成・`native:test` 緑を確認。回帰テスト `terminal leaf values follow the negamax convention` を追加。

### A-2. 【重大】exact ソルバが αβ カットオフの境界値を「厳密値」として TT 保存
- `apps/web/src/ai/alphaBetaAi.js` `exactSearch`。カットオフ後の `bestValue` は真値の上界/下界に過ぎないのに、全ノードを `exactSolved: true` で保存し、ヒット時は窓を無視して即返却していた。
- 修正: 元の窓に対する標準的な bound 分類（exact / lower / upper）で保存し、ヒット時は exact のみ即返却、bound は窓の絞り込みに使用。

### A-3. 【重大】TT エントリのスケール/視点混在
- exact ソルバ（最終スコア差 ±109 スケール、rootPlayer 相対）と ヒューリスティック αβ（`evaluateState` スケール）と MCTS の一次評価が同じテーブル形式を共有し、タイムアウトフォールバック時に相互汚染していた。
- 修正: 全エントリに `kind`（`exact_search` / `ab_heuristic` / `mcts_eval`）と αβ 系は `rootPlayer` を付与し、読む側は kind・rootPlayer 一致時のみ消費。`mctsAi.js` が親からの流入辺を `bestMove` として保存していた問題（意味論が逆）も削除。

### A-4. 【重大】ブラウザ AI の simulation 上限がタイム予算を無効化
- `difficulty.js` の `simulations ?? 128` と `main.js` の既定 `simulations: 96` により、expert/master が時間予算（1.5〜4 秒）のごく一部で探索を打ち切っていた（学習側は無指定なので arena で測る強さとブラウザの強さが乖離）。
- 修正: 既定の simulation 上限を撤廃（時間予算のみで制御）。保存済み設定の汚染を避けるため settings キーを v4 に更新。

### A-5. 【重大】PV-MCTS: candidateLimit 切り詰め後の prior 非正規化
- `rankByPolicy` 全体 softmax → `slice(0, candidateLimit)` で、保持児の prior 合計が 1 未満（広い局面では ≪1）になり PUCT の探索項と Dirichlet 混合が歪んでいた。
- 修正: 切り詰め後に再正規化（JS / Rust 同時、パリティ維持）。`rankByPolicy` 内の no-op slice も除去。

### A-6. 【重大】学習ループのシード衝突（自己対戦データの大量重複）
- `run_alphazero_loop.mjs` の iteration ストライドが `WORKER_SEED_STRIDE`（1000003）と同一で、iteration i / worker j+1 と iteration i+1 / worker j の乱数列が完全一致。モデルが昇格しない iteration では自己対戦の大半がビット同一で再生成されていた。
- 修正: iteration シードをハッシュ混合（`iterationSeed`）に変更。

### A-7. 【重大】replay buffer マニフェストの破損・上書きリスク
- `replay_buffer.mjs`: (a) マニフェスト書き込みが非原子的、(b) 破損時に**黙って空マニフェストを再作成**（既存 shard が孤児化し、次の shard-000001 が実データを上書き）、(c) shard ファイル名衝突時に上書き。
- 修正: temp+rename の原子的書き込み、既存マニフェストの parse 失敗はハードエラー、shard 追加時に既存ファイルを上書きしないようインデックスをスキップ。

### A-8. 【重大】`failOnFallback` が未配線（壊れた ONNX がヒューリスティックとして測定・昇格され得る）
- `ai_runtime.mjs` に安全弁は実装済みだが呼び出し側が誰も設定していなかった。モデルロード失敗時に `master_fallback`（実体は expert ヒューリスティック）が黙って arena / 自己対戦を代走し、データは `actor_difficulty: "master"` と誤ラベルされる。
- 修正: `normalizeTrainingAiSpec` で learned / master の既定を `failOnFallback: true` に（明示 `false` でオプトアウト可）。

### A-9. 【中】温度リサンプリングがポリシーターゲットを汚染
- `generate_dataset.mjs`: 探索用にリサンプルした手が選ばれると visit 分布を捨てて「その手 100%」の one-hot をターゲットにしていた（探索ノイズ自体を模倣学習）。
- 修正: ターゲットは常に教師（MCTS visit 分布、なければ教師手の one-hot）。打つ手だけをリサンプル結果にする。あわせて `playTrainingGame` の `policyTargetSource` 既定を CLI と同じ `"auto"` に（`run_selfplay_loop.mjs` 経由で visit ターゲットが黙って落ちていた）。

### A-10. 【中】`run_selfplay_loop.mjs` が毎 iteration ほぼ同一データを生成
- seed / Dirichlet / サンプリング温度が未指定で全 iteration 同一シード・探索なし。iteration 依存シードと探索ノイズ（alphazero ループと同じ既定）を付与。

### A-11. 【中】Web: 古いワーカー応答が別ゲームに適用される
- `main.js` の適用ガードが `turn`+`currentPlayer` のみで、New Game / Load JSON / Undo / モード変更を貫通していた。`gameEpoch` 世代カウンタと `isAiTurn()` 再チェックを導入。

### A-12. 【中】Web: Step ボタンが 2 手進む
- `paused` を一時的に false にする実装が render 経由の microtask と競合。`maybeStartAiTurn(force)` を導入し paused のまま 1 手だけ実行。

### A-13. 【中】Web: Load Game JSON 経由の XSS / 描画クラッシュ
- 貼り付けた JSON が無検証で `gameState` になり、`innerHTML` テンプレートに直接流れていた（pieceId / startAssignment / 履歴 / エラーメッセージ経由でスクリプト実行可能、または render が例外で恒久停止）。
- 修正: `validateLoadedState` による構造検証（盤・ピース ID・手履歴・座標）、`escapeHtml` を動的文字列に適用、パーサエラーの生文字列を表示しない、settings は既知キーのみ取り込み。

### A-14. 【中】Web: Undo が Human vs AI で実質無効
- 1 手だけ戻すと即 AI が同じ手を再生。人間の手番まで巻き戻すよう修正。

### A-15. 【中】Web: Skip ボタンを削除
- 合法手があってもスキップでき（公式ルール違反）、`applyMove` を迂回して `consecutivePasses` / 終局判定 / ply 規約を壊した状態を作っていた。パス（合法時のみ）は既存の Pass ボタンが担う。

### A-16. 【中】ワーカー/モデルセッションの復旧性
- あらゆるエラーでワーカーを破棄し ONNX セッションを失っていた → タイムアウト時のみ再作成。
- `modelRunner.js` / `ai_runtime.mjs` が失敗した Promise をキャッシュに残し、一度の一時的失敗で learned/master がセッション終了まで無効化 → 失敗時にキャッシュから除去。
- `learnedAi.js` の独自セッションキャッシュ（modelUrl を無視）を `modelRunner` に統合。
- `aiWorkerCore.js`: フォールバック手も違法なら黙って送らず ERROR に。違法 AI 手はゲームを止めて `aiHalted` 化。

### A-17. 【中】JS↔Python パリティテストが Linux で暗黙スキップ
- `learned.test.mjs` の python 解決が Windows 専用で、Linux/CI では 2 つのパリティテストが常に「実行せず PASS」だった。`scripts/run-python.mjs` と同等の解決（BLOKUS_PYTHON → .venv → PATH の python3/python）に修正。実行時間 0ms → 実測 ~200ms で実際に検証されるようになった。

### A-18. 【中】native クレートがコンパイル不能だった
- `mcts.rs` に f32/f64 型不一致と `sum()` の型推論エラーがあり、HEAD 時点で `cargo test` 自体が失敗（= パリティゲートが機能していなかった）。修正して 9 テスト全緑を確認。

### A-19. 【小】その他
- `export_onnx.py`: `--out` 省略時の既定を model-kind 別に（`export:onnx:pv` が policy 専用モデルを上書きしていた）。
- `run_learning_cycle.mjs --publish-model`: アリーナ**前**に公開モデルへコピーしていた → アリーナ後、candidate が負け越していなければ公開に変更。
- `arena_runtime.mjs`: alpha/beta 同名時に W/L 記録が崩壊 → 明示エラーに。

## B. 未修正の修正案（要判断・要再学習）

### B-1. 【最重要・要設計判断】state encoder の開始マスプレーンが両視点で同一セルを指す
- `packages/core/src/stateEncoding.js:35-40` / `training/blokus_shared.py` / `training/native/.../encoding.rs` の `startPointForPerspective` が owner と player の規約を混同しており、**plane 7（自分の開始マス）と plane 8（相手の開始マス）が常に同じセル**を指す。White 初手の corner 候補 plane は相手（Black）の開始マスを指す。3 実装が同じバグを共有しているためパリティテストは通過する（= バグを固定化している）。
- **単独で直すと悪化する**: 現状、盤面は player 1 視点で 180° 回転させる一方 action 空間は絶対座標であり、buggy な plane 7/8 が唯一の「自分がどちらの席か」を表す特徴になっている。plane だけ直すとテンソルが完全に席対称になり、同一入力に対して 180° 回転した異なるポリシー出力を要求する学習不能な曖昧性が生じる。
- 修正案（どちらか一方を選び、JS/Python/Rust を同時に変更）:
  - **案 (a) 推奨**: action もパースペクティブ変換する（player 1 は `x,y → 13-x,13-y`、orientation は 180° 回転後の global id に写像）。AlphaZero 標準形。ポリシーターゲット書き込みと logits 読み出しの両方を変換。
  - 案 (b): 盤面の回転をやめ、絶対座標に統一し「手番席」プレーンを追加（チャネル数 51→52、ONNX 入力形状変更）。
- どちらも**既存 ONNX モデル・データセットは全て無効**（AGENTS.md の規約どおり再生成・再学習・再エクスポートが必要）。`parity:golden` 再生成、`stateEncoding` のプレーン意味論を固定する単体テスト追加（現状ゼロ）もセットで。

### B-2. 【中】encoder が `startAssignment` を無視
- ブラウザ既定の `chooseStart` で player 0 が B=(9,9) から開始した場合、encoder は owner 0→A 固定のため開始マス/corner 候補プレーンが実際と食い違う（学習分布外入力）。B-1 の修正時に `state.startAssignment` を参照する仕様へ。学習側でも `--start-policy chooseStart` の混在を検討。

### B-3. 【中】value 正規化定数の不一致
- critical replay は `diff/89`（`branch_dataset_schema.mjs`）、トレーナの margin モードは `diff/109`、outcome モードは ±1。同じ value ヘッドに矛盾したターゲットが混ざる。共有定数（109）に統一し、critical replay 側はトレーナのモードに合わせて変換（または raw を保存して Python 側でのみ正規化）。MCTS 側 `normalizeValue`（/89）も合わせる場合は JS/Rust 同時変更。

### B-4. 【中】train/val 分割が同一ゲームのサンプルをリーク
- `train_policy.py` / `train_policy_value.py` の `random_split` はサンプル単位。同一ゲームの局面（同じ `final_score_diff`）が train/val 双方に入り、val_loss が楽観的でベストチェックポイント選択が歪む。`game_id` 単位の分割へ。

### B-5. 【中】分散キュー（multi-host モード）の共有マニフェスト競合
- `distributed_queue.mjs`: claim の rename は原子的だが、各ホストが古いメモリ像から `manifest.json` 全体を書き戻すため、他ホストの claim が pending に巻き戻る → `completeJob` が throw、ワーカーがクラッシュし完了ジョブが未完了のまま残る。ディレクトリ（pending/claimed/done）を真実のソースにし、マニフェストは参考情報に格下げする再設計を推奨。あわせて claimed ジョブのタイムアウト再キュー（現状ワーカー死亡でジョブが永久に残る）。

### B-6. 【小】Elo 記録の歪み
- `run_alphazero_loop.mjs`: N ゲームのマッチを 1 回の K-factor 更新で適用し、candidate の初期レートを opponent のレートに設定。昇格判定（score rate の信頼区間）には影響しないが、レジストリの絶対 Elo は自己参照的なインフレ。ゲーム毎の逐次更新か performance rating 化を推奨。

### B-7. 【小】性能（強さに直結する探索速度）
- `evaluateState` が 1 回の呼び出しで合法手全生成を 4 回実行（αβ/MCTS の leaf 評価を支配）。
- `applyMove` が検証のため全合法手を再生成し、`cloneState` が `moveHistory` を毎手 `structuredClone`（探索中は O(n²)）。探索用に `applyMoveUnchecked` + 履歴省略の導入を推奨。
- `hashState` が毎ノード盤面全体の文字列を構築、TT は無上限。Zobrist ハッシュ + サイズ上限を推奨。
- 合法手生成が 91 orientation × 196 セルの総当たり。corner 候補セルを anchor にする生成で桁違いに削減可能。

### B-8. 【小】その他
- `scripts/serve.mjs`: COOP/COEP ヘッダが無く onnxruntime-web のマルチスレッドが無効化。stream の error ハンドラ欠如、URL の percent-decode 欠如。
- `scripts/build.mjs` がテストごと dist に同梱 / `verify-build.mjs` が worker・vendor・models の存在を検査しない。
- `engines.js` の `decideAiMove`（未使用）が `policy_value_mcts` を expert に写像しており `difficulty.js` と矛盾。削除推奨。
- `policyValueMctsAi.js` のエラー分類が `message.includes("Unexpected")` 依存。型付きエラーへ。
- ビームサーチのタイムアウト後の leaf 値スケール混在（`quickLeaf` と `evaluateState`）。
- `train_policy.py` は `selected_action`（実際に打った手）を学習するため、温度リサンプリング使用時は探索ノイズを模倣する（PV トレーナは A-9 で解消済み。旧トレーナ利用時は注意）。
- critical replay の pass-only フォールバックが `rawScoreDiffs` に正規化済み値を入れる（`replay_from_state.mjs`）。ほぼ到達不能だが要修正。
- `chooseFinalChild` などの逐次 `rng() < 0.5` タイブレークは 3 つ以上の同率で一様でない。
